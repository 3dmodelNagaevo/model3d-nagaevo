# Как устроены сайт и бот «3D модели в Нагаево»

Полное описание системы: что из чего состоит, где что лежит, как всё работает и как это чинить. Написано так, чтобы по нему мог разобраться и сам владелец, и любой другой ИИ-помощник. Актуально на 21.11.2026.

## 1. Коротко: как всё связано

Вы выкладываете пост в канал MAX → бот получает событие и сразу запускает обновление → программа синхронизации на GitHub читает канал, делает из постов карточки товаров, сжимает фото и выкладывает сайт → сайт 3dnagaevo.ru показывает каталог. Управлять всем можно из бота в MAX (кнопки и команды) или из приложения управления внутри MAX.

Схема:

```
Канал MAX ──(webhook)──► Бот в Яндекс Облаке ──► запускает синхронизацию на GitHub
                                │                          │
   вы/админы ◄──кнопки, ответы──┘                          ▼
                                             GitHub Actions: scripts/sync_max.py
                                             читает канал → catalog.json, фото, страницы
                                                           │
                                                           ▼
                                             GitHub Pages → https://3dnagaevo.ru
```

Нигде не арендуется сервер: сайт бесплатно хранится на GitHub Pages, бот работает в бесплатной облачной функции Яндекса, синхронизация — бесплатные запуски GitHub Actions. Платный только домен (Selectel).

## 4. Как оформлять посты, чтобы они попали на сайт

Синхронизация разбирает каждый пост канала:

- **Первая строка** — название товара (можно с ценой: «Дракон — 200 ₽»).
- **Строка «Стоимость:» или «Цена:»** — цена. Пост с ценой считается товаром. Без цены и без строк размера/цвета пост на сайт не попадает (это обычные новости).
- **«Размер:», «Цвет:», «Материал:»** — поля карточки.
- **Хэштеги** определяют категорию: `#авто`, `#игрушки`, `#антистресс`, `#фигурки`, `#декор`, `#длядома` (можно `#Для_дома` — подчёркивания не важны), `#подарки`, `#наборы`, `#геймерам` и др. Без тега категория угадывается по словам в тексте; если не угадалась — «Разное». Список тегов и слов — в `scripts/sync_max.py` (`HASHTAG_CATEGORIES`, `KEYWORD_CATEGORIES`).
- **`#нетнасайте`** (или `#скрыть`) — пост не попадёт на сайт. **`#отзыв`** — пост попадёт в раздел отзывов. **`#промокод`** — посты с промокодами (на сайт как товар не идут).
- **Фото** поста становятся фото товара (сжимаются до 1200 px, плюс миниатюры 600 px).
- Ссылки на заказ и прочие URL из описания убираются автоматически.
- Удалили пост в канале — товар исчезнет с сайта. Изменили — изменится.

Образец поста — кнопка «📝 Шаблон» в боте.

## 5. Сайт (https://3dnagaevo.ru)

Файлы сайта:

- `index.html` — весь сайт (одна страница): шапка с меню, «Последнее в канале», блок промокодов, новинки, хиты недели, каталог с поиском/фильтрами/сортировкой и кнопкой «Показать ещё», «Найти под заказ», «Своя модель» (форматы STL/3MF/OBJ/STEP, моделирование), «Как заказать», FAQ, отзывы, условия, контакты. Карточка модели открывается поверх: фото, описание, поле промокода с проверкой, «Заказать в MAX» (копирует текст заказа и открывает личку), Telegram, звонок, «Посмотреть модель в канале», отзывы о модели с формой, похожие модели, избранное.

- `photos/`, `img/`, `qr/` — фото товаров, картинки сайта, QR-коды (сайт, канал, листовка).
- `sitemap.xml`, `robots.txt` — для поисковиков (автоматически).
- `app.html` + `app.js` — приложение управления (см. раздел 7).

Особенности:

- Технические работы: баннер сверху или экран «Технические работы» (раздел 9).
- Устройства админов не учитываются в Метрике (отметка ставится при открытии приложения или по ссылке `https://3dnagaevo.ru/?nometrika=1`; снять — `?nometrika=0`).
- Цели Метрики: order_max, order_tg, order_call, fav_send_max, open_model, share, channel_max, get_discount, promo_check, review_sent и др.

## 6. Бот

### 6.1. Как он работает
- **Основной бот** — облачная функция Яндекса. В самой функции лежит только загрузчик `yandex/index.py`; он берёт код бота `yandex/bot.py` из GitHub и проверяет обновления раз в 5 минут. Поэтому любые правки `yandex/bot.py` в репозитории попадают в бота сами. Если в новой версии ошибка — продолжает работать старая.
- MAX присылает в функцию события (webhook): сообщения боту, нажатия кнопок, новые/изменённые/удалённые посты канала (на них бот сразу запускает синхронизацию сайта).
- **Запасной бот** — `scripts/bot.py` внутри синхронизации на GitHub. Он работает, только если вебхук выключен.
- Первичная настройка/переподключение: открыть в браузере `адрес_функции?setup=SECRET` (выключить — `?off=SECRET`, проверить — `?check=SECRET`).

### 6.2. Кто может управлять
- Владелец канала — всегда всё.
- Админы канала — только если им дан доступ. «⭐ Полные права» — всё как у владельца, включая выдачу прав.
- **Права по разделам** (`/права N` в боте или «Ещё → ⚙️ Права» в приложении): 🧾 Продажи и заказы, 🧩 Товары, 📸 Посты, 🎟 Промокоды, 💬 Отзывы, 📈 Статистика, 🛠 Сайт (обновить, тех. работы, копия), 👥 Доступ.
- Забрать доступ и «убрать все права» — только с подтверждением.
- Хранится в `access.json` (`allowed`, `full`, `perms`).

### 6.3. Меню и команды для админов
Кнопки меню: 📊 Статус, 📈 Статистика, ✅ Продано, 🧾 Продажи, 📜 История, ↩️ Отменить, 🔥 Топ, 🔄 Обновить, 🙈 Скрыть, 👁 Вернуть, 💰 Цена, 🖼 Обложка, 💬 Отзыв, 🗂 Отзывы, 📸 Новый пост, ✏️ Изменить пост, 🎟 Промокоды, 📝 Шаблон, 👥 Доступ, 🗄 Резервная копия, 🚧 Тех. работы, ❓ Помощь, 🛠 Приложение управления.

Если нажать команду без номера, бот сам спросит номер (ждёт ответ 15 минут). Основные команды:

- Продажи: просто номера `38` или `38 2` (по строке на товар) — отметить продажу; `/продажи`, `/история`, `/отменить`, `/удалить продажу 7`, `/сбросить продажи 38`.
- Товары: `/цена 12 300`, `/цена 12 сброс`, `/скрыть 12`, `/показать 12`, `/обложка 12` (кнопки выбора фото).
- Посты: `/пост` + фото (бот опубликует), `/изменить 12 цена 350` / `размер` / `цвет` / `название`, `/изменить 12` — получить весь текст и прислать исправленный. Бот меняет только посты, которые сам опубликовал.
- Отзывы: `/отзыв текст` (+ фото, `№12` в тексте — привязать к модели), `/отзывы`, `/удалить отзыв 3`, `/проверка`, `/одобрить 5`, `/отклонить 5`.
- Промокоды: `🎟 Промокоды`, `/код ЗИМА15` — проверить и активировать.
- Сайт: `/обновить`, `/статус`, `/топ`, `/стата`, `/метрика сброс` / `/метрика всё`, `/копия`, `/техработы`.
- Доступ: `/доступ`, `/права 2`, `/разрешить 2`, `/запретить 2`.
- Ответ покупателю, написавшему боту: кнопка «💬 Ответить» под его сообщением.

### 6.4. Что видят покупатели
Отдельное меню (админского они не видят): «🎁 Получить скидку» (показывает действующие промокоды или выдаёт личный код за подписку), «🛍 Каталог», «📣 Канал», «✍️ Написать мастеру». Всё, что покупатель напишет боту, пересылается админам с кнопкой «Ответить». Список команд под «/» в MAX содержит только безопасные команды (Начать, Получить скидку).

### 6.5. Групповой чат «ссылки на модели»
Бот, добавленный в групповой чат, сохраняет присланные ссылки на модели (MakerWorld, Printables, Thingiverse и др.) в `links.json`: теги из `#тегов`, поиск `найти дракон`, `/ссылки`, `/теги`, `/тег`, `/готово N` (напечатано), `/план`, `/удалить ссылку N`, `/импорт`.

### 6.6. Автоматические сообщения
- Каждый понедельник — отчёт за неделю (продажи, просмотры).
- Если в канале нет постов больше суток — напоминание (раз в сутки, днём по Уфе).
- Новые отзывы с сайта, заказы/сообщения покупателей, выданные промокоды, публикация промокодов по расписанию.
- По воскресеньям — резервная копия.

## 7. Приложение управления (мини-приложение MAX)

Адрес: `https://3dnagaevo.ru/app.html`, прописан в business.max.ru → бот → Настройки → ссылка на мини-приложение. Открывается кнопкой «🛠 Приложение управления» или «Открыть» в чате бота. Вход проверяется подписью MAX (initData), подделать нельзя; покупателю вместо приложения показывается каталог.

Вкладки (скрываются, если нет прав):
- **Сводка** — продажи за 7/30 дней, модели, отзывы на проверке, промокоды, график продаж, популярное; кнопки: Новый пост (текст+фото), Тех. работы, Статус сайта, Обновить сайт, Резервная копия, Статистика, Открыть сайт.
- **Товары** — поиск/фильтры; карточка: цена, продажа, обнулить «Продано», главное фото, скрыть/вернуть, изменить пост.
- **Продажи** — отметить продажу, история, удалить отметку, отменить последнюю.
- **Промо** — список промокодов и действия, новый код, автовыкладка, скидка за подписку, проверка кода.
- **Метрика** — периоды (сегодня, вчера, 7/30 дней, месяц, прошлый месяц, 90 дней, год, свой), посетители по дням и часам, цели, модели, источники, наши ссылки (листовка/канал/бот), устройства, города, поисковые фразы; «Начать отсчёт с этого момента» (двойное подтверждение), «Показать всё временно», «Показывать всё».
- **Отзывы** — добавить отзыв (имя, модель, звёзды, текст, фото), на проверке (опубликовать/удалить), опубликованные (убрать).
- **Ещё** — доступ и права админов, библиотека ссылок.

Технически: `app.js` загружается всегда свежим (`app.js?v=время`), код обёрнут в функцию — скрипт MAX объявляет свои глобальные имена (`u` и др.). Действия выполняются через API функции (`?app=1`): `dash`, `cmd` (любая команда бота, ответ возвращается в приложение), `metrika_data`, `review_add`, `post_new`.

## 8. Промокоды и скидки

- Создать: «🎟 Промокоды → ➕ Новый» — `КОД СКИДКА АКТИВАЦИИ ДНЕЙ`, например `ЗИМА15 15% 3 7`; `авто` — код придумает бот (ПОДАРОК27 и т.п.).
- Дальше: опубликовать в канал (пост с кнопками «📋 Скопировать промокод», «Заказать», «Каталог»), поставить в очередь автовыкладки, включить без поста (выдавать лично), удалить.
- **Активация** засчитывается, когда заказ выполнен: после отметки продажи бот предлагает «🎟 Был промокод … — активировать». В посте обновляется «осталось N», при окончании — «⛔️ Промокод больше не действует».
- **Автовыкладка**: `пт 18:00 10% 3 7` — каждую пятницу в 18:00 по Уфе (выкладывает синхронизация, возможна задержка 5–15 минут).
- **Скидка за подписку**: бот проверяет подписку на канал и выдаёт личный одноразовый код (один на человека). Личные коды хранятся только как хэш — на GitHub их не видно.
- Проверка кода на сайте (поле в карточке) ничего не списывает; защита от перебора — 30 проверок в час.
- Данные: `promos.json`; логика расписания — `scripts/promo.py`, команды — `yandex/bot.py`.

## 9. Технические работы

`🚧 Тех. работы` в боте или «Сводка → Тех. работы» в приложении:
- 🟡 **Баннер** — сайт работает, сверху оранжевая полоса с вашим текстом.
- 🔴 **Закрыть сайт** — посетители видят экран «Технические работы» с текстом, временем окончания и кнопками связи (с подтверждением).
- 🟢 **Выключить**.
Админы видят сайт как обычно (с пометкой). Включается за 1–3 минуты (бот сразу запускает синхронизацию). Хранится в `settings.json` → `maint`, на сайт попадает через `catalog.json`.

## 10. Отзывы

- С сайта (форма в карточке модели, имя обязательно) → автопроверка ботом: нормальные публикуются сразу; с матом/ссылками/телефонами/капсом/оценкой 1–2★ — на проверку админам (кнопки «Опубликовать»/«Удалить»); явный спам отбрасывается. Не больше 3 отзывов в час с одного адреса.
- Из бота/приложения — публикуются сразу.
- Из канала — посты с `#отзыв`.
- Данные: `reviews.json` (`reviews` — опубликованные, `pending` — на проверке), фото — `reviews/raw/`.

## 12. Автоматические процессы GitHub

- `.github/workflows/sync.yml` — каждые 5 минут (GitHub может запускать с опозданием), при каждом изменении кода и по команде бота: ставит сертификаты Минцифры (нужны для API MAX), запускает `scripts/sync_max.py`, сохраняет данные коммитом, выкладывает сайт на Pages. Изменения `links.json`, `promos.json`, `settings.json` сами по себе сайт не перевыкладывают.
- `.github/workflows/backup.yml` — по воскресеньям ~20:17 по Уфе и по кнопке: собирает архив (все файлы + полная история git + инструкция) и присылает его в бота. Нигде не хранится.

Скрипты: `sync_max.py` (главный), `maxapi.py` (запросы к MAX, загрузка файлов), `photos.py` (сжатие фото), `pages.py` (страницы моделей, QR, sitemap), `promo.py` (промокоды по расписанию), `outbox.py` (разовые посты), `bot.py` (запасной бот, отчёты, уведомления), `backup.py` (резервная копия).

## 13. Частые задачи «как сделать самому»

- **Поменять телефон, ссылки, Telegram** — `config.js` (на GitHub: открыть файл → карандаш → Commit). Через 1–3 минуты сайт обновится.
- **Добавить категорию/тег** — `scripts/sync_max.py`, словари `HASHTAG_CATEGORIES` (тег → категория) и `KEYWORD_CATEGORIES` (слова → категория).
- **Поменять тексты сайта** (FAQ, условия, «Своя модель») — `index.html`, поиск по тексту.
- **Срочно обновить сайт** — кнопка «🔄 Обновить» или GitHub → Actions → «sync» → Run workflow.
- **Резервная копия сейчас** — «🗄 Резервная копия».
- **Вернуть удалённое** — из архива копии: загрузить нужный файл в репозиторий (Add file → Upload files).
- **Выложить пост от бота с картинками заранее** — добавить запись в `outbox.json` (`id`, `text`, `images` — пути в репозитории, `buttons` — [[текст, ссылка]]).

## 14. Если что-то сломалось

1. **Сайт не обновляется** — GitHub → Actions → последний запуск «sync»: красный крестик → открыть лог. Частые причины: истёк `MAX_TOKEN`, временный сбой MAX/GitHub (следующий запуск обычно проходит).
2. **Бот не отвечает** — Яндекс Облако → функция → Логи. Проверить `адрес_функции?check=SECRET`. Если вебхук слетел — открыть `?setup=SECRET`.
3. **Приложение пустое/ошибка** — на экране будет текст ошибки; закрыть приложение и MAX полностью, открыть заново. Старые встроенные браузеры не понимают новый синтаксис JS (`?.`, `??`) — его в коде нет специально.
4. **Сайт не открывается по домену** — проверить DNS в Selectel и GitHub → Settings → Pages (Custom domain 3dnagaevo.ru, Enforce HTTPS).
5. **Метрика пустая во вкладке** — нет `METRIKA_TOKEN` в функции или он истёк.
6. **Полный крах / новый аккаунт** — восстановить из архива резервной копии (инструкция внутри архива, файл «ПРОЧИТАЙ_МЕНЯ.txt»).

## 15. Для другого ИИ: технические заметки

- MAX Bot API: хост `platform-api2.max.ru` (нужны корневые сертификаты Минцифры), запасной `platform-api.max.ru`. `GET /chats` отключён с июня 2026 — id канала берётся из `channel_id.txt`. Админы канала: `/chats/{id}/members/admins` (`is_owner`). Подпись вебхука — заголовок `X-Max-Bot-Api-Secret`. Пока вебхук включён, long polling не работает. Бот редактирует только свои сообщения; `attachments` не передан при PUT — вложения сохраняются, `[]` — удаляются. Картинки по URL MAX может не принять — надёжнее загрузка `/uploads?type=image`. Кнопки: `callback`, `link`, `clipboard`; deep-link бота `?start=payload` → событие `bot_started` с `payload`.
- Мини-приложение: скрипт `https://st.max.ru/js/max-web-app.js`, `window.WebApp.initData`; проверка подписи как в Telegram (HMAC-SHA256 с ключом `HMAC("WebAppData", токен)`).
- Метрика: Reports API `api-metrika.yandex.net/stat/v1/data`, отсечка «с момента» — фильтр `ym:s:dateTime>='…'` в часовом поясе счётчика.
- Ограничения РФ: Cloudflare/Netlify ненадёжны, поэтому GitHub Pages + Яндекс Облако. Закон 152-ФЗ — плашка cookies и политика.
- Код и тексты интерфейса — на русском. Стиль сайта: шрифты Unbounded + Onest, цвета кобальт #2F4BFF, оранжевый #FF6B2C, чернила #1B1F3B, фон #EEF0F4.
- Правило работы с репозиторием: делать `git pull --rebase` перед пушем — бот и синхронизация сами коммитят данные.
